Places a ticket into the inbox with an atomic write — the daemon can never claim a half-written file. The filename comes from the ticket's id (falling back to the source filename); - reads the ticket from stdin, which is how other tools pipe work in. 

junco submit fix-tide-rounding.md
cat ticket.md | junco submit -
queued inbox/fix-tide-rounding.md

Three further forms share the verb. --dry-run <file> reports where the ticket would go (destination: issue|inbox, one reason: per cause), which frontmatter survives the issue route, the effective timeout, and the same results as junco lint — writing nothing. --as-issue <file> files the ticket as a parked, unlabeled GitHub issue that only a human's trigger label launches; a valid timeout_minutes is carried, clamped to 1–480 minutes. --plan <file> --repo <path> compiles an approved junco-plan fence into its dependency-ordered child tickets (--as-issue --plan parks the fence as an issue instead). 

junco submit --dry-run fix-tide-rounding.md
destination: issue
reason: repo acme/api is bridge-watched; github + bot account enabled
carried: timeout_minutes=60
dry run — nothing submitted
warn — the inbox is a code-execution boundary: a PR-flow ticket runs an agent against the repo it names, as you. Keep the inbox on a disk only you can write, and confine targets with git.allowedRepoRoots.
